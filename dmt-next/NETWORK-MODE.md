# A PC 서버 / B·C·D 클라이언트

## A PC에서 시작

1. 최신 버전으로 업데이트하고 **서버·클라이언트 / 성능 측정**을 연다.
2. 기존과 동일하게 NAS 접속 설정과 데이터 경로가 동작하는 Windows 계정으로 실행한다.
3. **A PC에서 허용할 데이터 폴더**에 실제 BBT/Skipdata, SKI, TXT/JSON 폴더를 추가한다. UNC 경로도 입력할 수 있다. 모델 설정에 저장된 경로도 사용 전에 허용 여부를 확인한다.
4. 처음에는 **동시 처리 세션 상한 1**로 시작한다. 상한은 A의 로컬 작업도 포함하며 1–4 사이에서 수동으로 설정한다.
5. **서버 모드 시작**을 누르고, 표시된 A PC 접속 주소와 B/C/D 각각의 전용 접속 키를 전달한다. 서버를 켰던 설정은 앱 재시작 시 복원한다.
6. Windows 방화벽에서 선택한 TCP 포트(기본 8765)를 필요한 사설망 접속 PC에만 허용한다. 앱이 방화벽 규칙을 자동으로 생성하지 않는다. B/C/D는 A로 네트워크 접속이 가능해야 한다.

HTTP 기반의 사내망/VPN용 기능이다. 포트 포워딩으로 인터넷에 공개하지 않는다. GitHub에는 프로그램 코드와 설치 파일만 배포하며 접속 키·NAS 비밀번호·원본 데이터·측정 로그는 올리지 않는다. 외부 접속이 필요한 환경은 조직의 VPN을 사용한다. HTTPS 게이트웨이는 별도 접속 정책 구성이 필요하다.

## B·C·D에서 접속

브라우저에서 A의 주소를 열고 자신의 접속 키를 입력한다. 또는 설치된 Electron 앱의 동일 메뉴에서 **클라이언트 모드로 연결**에 A 주소를 입력한다. 클라이언트 창은 Node/Electron 파일 접근 권한이 없는 별도 샌드박스 창이다. 상단 **모드** 메뉴 또는 클라이언트 창 종료로 로컬 관리 화면으로 돌아갈 수 있다.

한 키는 하나의 독립 작업 공간이다. 같은 키를 여러 PC에서 사용하면 같은 화면을 공유하므로 각 PC에 B/C/D 서로 다른 키를 배정한다. 입력·Qt 설정·모델 프로필·수율 자동 연결·결과 폴더·로그는 작업 공간별로 분리한다. 소스 TXT의 검증된 SQLite 읽기 캐시는 A에서 공유한다. A의 NAS 비밀번호는 클라이언트로 전달하지 않는다.

기존 10개 탭을 원격에서도 사용한다. 경로 선택은 **A PC의 허용 폴더** 기준이며, 필요한 경우 B/C/D의 TXT/JSON/템플릿을 업로드할 수도 있다(파일당 최대 8 MB). 저장 대화상자에는 파일명만 입력한다. 저장 결과는 자신의 **내 결과 다운로드** 목록에서 받는다. 이미지 하위 폴더도 포함되며 **결과 전체 ZIP 다운로드**로 최대 10000개 결과 파일을 한 번에 받을 수 있다. 일괄 추출의 저장 폴더는 작업 공간의 결과 폴더를 선택하면 된다. 동일 파일명도 서로 다른 키의 결과와 충돌하지 않는다.

여러 사용자가 요청할 수 있으며 상한을 초과하면 대기한다. 대기 중인 입력은 잠기고 대기를 취소할 수 있다. 실행 중인 Gathering은 기존 중지 버튼을 사용한다. 중복 Strip/SKI 검수 및 재작업 날짜 선택은 요청한 사용자의 화면에서 진행한다. 검수 대기도 활성 작업으로 취급하므로 검수가 끝나야 자리가 비워진다. 원본을 이동하는 **LM Data의 BK 이동 / PMK 저장**은 A PC에서만 실행한다.

브라우저를 닫아도 A의 작업은 계속된다. 다시 같은 키로 접속하면 진행 중인 검수와 저장된 결과를 이어서 확인할 수 있다. A 앱 종료·업데이트는 활성/대기 작업이 있을 때 차단한다. A PC 종료·절전·Windows 로그아웃 중에는 서비스를 제공하지 못한다. A의 비정상 종료 후에는 자동으로 분석을 재실행하지 않으므로 결과를 확인하고 필요한 작업을 다시 요청한다. 연결 오류가 발생한 분석 엔진은 A에서 작업 상태를 확인한 후 서버를 종료하고 다시 시작한다.

## 성능 측정과 상한 조정

측정은 기본으로 켜져 있으며 원본을 훑는 부하 시험을 자동으로 실행하지 않는다. 실제 IVS/Gathering/수율 작업을 수행하면서 다음을 기록한다.

- A 전체 CPU 사용률, 사용/여유 메모리 및 전체 네트워크 송수신 속도
- 분석 프로세스별 PID·RSS 메모리·CPU 사용률·프로세스 I/O 누계
- 작업 화면·모델·LOT·버튼, 처리 시간(검수 대기 포함), 대기열 시간, 오류/중지 여부

프로세스 CPU는 논리 CPU 수로 나눈 전체 PC 용량 기준이다. 네트워크 수치는 NAS 전용 수치가 아니라 **A PC 전체 트래픽**이다. 1초보다 짧은 작업은 프로세스 피크 샘플이 없을 수 있다. `idle / 엔진 대기`는 계산 엔진이 종료 상태로 돌아왔다는 의미이며 데이터 정확성 검증 성공을 뜻하지 않는다.

최소 3초 이상 걸린 실제 분석 작업이 3건 이상이고, 서로 다른 LOT가 3개 이상이며 최근 3건의 CPU 피크 <65%, 사용 메모리 피크 <75%이면 **다음 시험 동시 처리 수 2**를 제안한다. 설정을 자동으로 바꾸지 않는다. 이것은 처리량 보장이 아닌 다음 비교 시험 권장값이다. NAS 병목은 CPU 여유만으로 판정할 수 없으므로 1개와 2개 실행의 시간·트래픽·오류를 비교해야 한다. 파일 선택/내보내기 대기와 오류/중지 작업은 권장값 산정에서 제외한다.

실제 LOT 3개 이상 테스트한 뒤 **측정 JSON 내보내기**로 로그를 제공하면 지표를 비교해 상한을 조정할 수 있다. 최근 샘플 최대 1시간 및 최근 작업을 내보내며, 디스크 로그는 `measurements.jsonl`과 회전 백업에 보관한다. 앱 업데이트는 이 데이터를 유지한다.

## 繁體中文

A 電腦：開啟「伺服器・用戶端 / 效能測量」，加入允許讀取的 BBT、SKI、TXT/JSON 資料夾，初次以同時處理 1 個工作階段啟動伺服器。提供 A 的連線位址以及各電腦不同的 B/C/D 專用金鑰，並於 Windows 防火牆允許必要內網電腦使用選定 TCP 連接埠。

B/C/D：透過瀏覽器開啟 A 的位址，或使用 Electron 的用戶端模式，輸入自己的金鑰。每個金鑰有獨立的輸入、模型設定、原始分析引擎、檢查對話框及結果資料夾。支援既有 10 個頁面與韓文/繁體中文切換。檔案選取以 A 的允許資料夾為準，也可上傳本機小型檔案；結果透過「下載我的結果」取得。關閉瀏覽器不會停止 A 上的工作。

測量預設啟用。請實際處理至少 3 個不同 LOT，再匯出測量 JSON，比較整機 CPU/記憶體/網路、程序記憶體、處理及排隊時間。系統僅提供保守的下一次測試建議，不會自行提高同時處理上限。網路數據為整台 A 電腦的流量，並非 NAS 專用流量。等待使用者檢查的時間也會計入；引擎閒置不代表資料已驗證成功。

此功能適用於內網或 VPN 的 HTTP 連線，請勿直接公開至網際網路。原始資料移動功能僅限於 A 電腦。伺服器有執行中或排隊工作時，會阻止程式結束與更新。A 電腦休眠、關機或登出時無法提供服務；非正常關閉後須確認結果並重新要求必要的工作。
