# 0.4.13 원본 TXT 보관기간 정리

원본 IVS/FVI/VRS 공유 경로에서 **생성 시각과 수정 시각 중 더 최근 시각이 30일보다 오래된 `.txt`**만 정리합니다. 상위 경로를 탐색할 때 처리해야 하는 오래된 파일 수를 줄이는 기능입니다. 생성 시각이 최근으로 기록된 파일이나 최근 수정된 파일은 남깁니다. 파일명에 있는 날짜로 판정하지 않습니다.

## A PC 사용 순서

1. 왼쪽 하단의 **30일 지난 TXT 정리**를 엽니다.
2. **IVS/FVI/VRS 설정 경로 불러오기**를 눌러 현재 게더링 설정의 설비 경로를 가져옵니다. 한 줄에 하나씩 표시되며 필요한 경로만 남기거나 추가할 수 있습니다. 실제 원본 TXT 경로인지 확인합니다.
3. **삭제 대상 미리보기**를 실행합니다. 이 단계에서는 원본을 삭제하지 않습니다. 경로별 대상 수량·용량·오류와 파일 샘플·UTC 기준 시각을 확인합니다. 샘플은 최대 50개이며 전체 내역은 로그에 있습니다.
4. 일회 정리는 **미리보기 대상 지금 삭제**를 누릅니다. 원본의 영구 삭제라는 확인창에서 경로와 수량을 검토한 뒤 진행합니다. 휴지통에 보관되지 않고 자동 백업도 만들지 않으므로 보존할 자료는 별도 백업 후 실행합니다.
5. 계속 정리하려면 미리보기 후 **자동 정리 켜기**를 누르고 확인합니다. 처음에는 다음 유휴 시점에 실행하고, 이후 정상 실행 후 24시간마다 유휴 상태에서 진행합니다. 필요 없으면 **자동 정리 끄기**를 누릅니다.

기본 상태는 **자동 정리 꺼짐**입니다. 배포나 업데이트만으로 원본이 삭제되지 않습니다. 켜기 전에는 모든 선택 경로의 미리보기가 정상이어야 합니다. 이후 자동 실행 중 일부 경로가 실패하면 정상 경로의 결과와 실패를 각각 기록하고, 약 1시간 후 유휴 상태에서 재시도합니다.

## 범위와 보호 조건

- 선택한 원본 경로와 하위 폴더의 대소문자 구분 없는 `.txt`만 대상입니다. XML·RPT·SKI·이미지와 폴더 자체는 삭제하지 않습니다.
- 앱 원본 보관소·캐시·검증/분류 데이터·시스템 경로·드라이브 루트·관리 공유 루트 등은 정리 대상으로 허용하지 않습니다. 링크 경로와 링크 파일은 건너뛰거나 오류로 표시합니다.
- 삭제 직전에 미리보기 당시와 같은 파일인지, 크기·시각·30일 조건이 그대로인지 확인합니다. 바뀐 파일은 건너뛰며, 열려 있는 파일이나 삭제 권한이 없는 파일은 실패로 남길 수 있습니다.
- 미리보기는 10분 동안 유효합니다. 경로를 수정하거나 미리보기가 바뀌면 다시 미리보고 승인해야 합니다. 새 미리보기는 이전 미리보기를 무효화합니다.
- A의 분석·대기·파일 전송 작업이 있으면 정리를 연기합니다. 정리 중에는 새 분석 요청을 받지 않으며, B/C/D에는 완료 후 다시 시도하라는 메시지가 표시됩니다. 이미 실행 중인 분석 중간에 삭제하지 않습니다.
- B/C/D 웹/클라이언트 창에는 관리 API를 제공하지 않습니다. 원본 정리는 데이터 접근 권한이 있는 A의 로컬 관리 화면에서 설정합니다.

## 진행·중지·로그

화면에서 진행 상태, 삭제 기준 UTC, 원본 경로, 대상 파일 수·용량, 삭제·건너뜀·실패 수를 확인합니다. 미리보기는 진행률 미확정 표시, 삭제는 처리 수량 기준 진행률을 표시합니다.

**중지**는 이후 작업을 취소합니다. 이미 삭제된 파일은 복구되지 않습니다. 응답 없는 Windows/SMB 호출은 반환될 때까지 중지가 지연될 수 있습니다. 상태가 불확실하면 정리 중 상태와 작업 차단을 유지합니다. 정리 완료 또는 중지 확인 후 창을 닫습니다.

**정리 로그 폴더 열기**에서 전체 대상과 결과를 확인합니다. 로그는 A의 `%APPDATA%/dmt-analysis-next/cache/collector/maintenance`에 보관합니다. 각 실행의 JSON과 삭제 전/후 기록 JSONL이 있으며, 로그를 기록할 수 없으면 삭제하지 않거나 추가 삭제를 중단합니다. 설정은 `txt-cleanup.json`에 저장되고 앱 업데이트 후에도 유지합니다.

앱 캐시와 원본 스냅샷은 삭제하지 않지만, 앱이 모든 오래된 TXT의 내용을 보관한 것은 아닙니다. **캐시를 원본 전체의 백업으로 간주하지 마세요.** 삭제한 원본은 Windows 휴지통에서 되살리는 기능을 제공하지 않습니다.

## 자동 실행 범위와 성능

자동 정리는 승인한 경로 목록만 사용합니다. 이후 게더링의 IP/모델 경로를 변경했다면 자동 정리를 먼저 끄고, 정리 화면에서 경로를 다시 불러온 뒤 미리보기·켜기 승인을 갱신하세요. 입력란 편집만으로 승인 경로가 바뀌지는 않습니다. 실행 중인 앱에서만 동작하며, A가 꺼져 있으면 다음 실행 후 유휴 시점까지 기다립니다.

첫 미리보기와 대량 삭제 자체에는 시간이 걸립니다. 오래된 파일이 줄어들면 다음 TXT 추적의 디렉터리 조회량이 줄 수 있지만, NAS 연결·디렉터리 수·최신 데이터 양에 따라 차이가 있으므로 속도 향상 배수를 보장하지 않습니다. IVS NAS 전체 XML Trial 탐색은 이 기능의 삭제 대상이 아닙니다.

Windows에서는 검증한 파일 핸들을 사용해 삭제합니다. 구현은 [Microsoft SetFileInformationByHandle 문서](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)를 기준으로 하며, 공유폴더에서의 삭제 성공 여부는 실제 Windows/SMB 권한에 따라 달라집니다.

## 繁體中文操作

1. 在 A 電腦左下開啟「清理超過 30 天的 TXT」。
2. 按「載入 IVS/FVI/VRS 設定路徑」，核對每行的原始共享資料夾，僅保留需要清理的路徑。
3. 按「預覽刪除對象」，確認各路徑數量、容量、錯誤、樣本與 UTC 時間。預覽不刪除原始檔，10 分鐘後須重新預覽。
4. 一次清理使用「立即刪除預覽對象」；核對永久刪除確認視窗後執行。檔案不進入資源回收筒，也不會自動備份，需保留的資料請先另作備份。
5. 持續清理時，預覽後按「啟用自動清理」。預設停用；確認啟用後先於下一次閒置時執行，之後每 24 小時閒置時再次清理。有分析或排隊工作時延後；失敗後約 1 小時重試。可隨時在工作完成後停用。

只刪除建立／修改時間較晚者已超過 30 天的 `.txt`，包含子資料夾；近期建立／複製／修改的檔案保留。不刪除 XML、RPT、SKI、影像、資料夾及程式快取。連結、系統／磁碟根路徑、檔案已變更、占用或權限問題會拒絕、略過或記錄失敗。

清理前後皆記錄檔案及結果，無法寫入日誌時不刪除或停止後續刪除。使用「開啟清理紀錄資料夾」查看完整 JSON／JSONL。停止不會復原已刪除的檔案；原始快取並非所有舊檔的完整備份。

B/C/D 不能經遠端介面設定或執行刪除。清理中新的分析請求會提示稍後重試。此功能與 IVS NAS 全部 XML Trial 掃描分開，不會刪除 XML。啟用的路徑不會隨後續型號／設備設定自動擴大，變更來源後請重新預覽及確認。
