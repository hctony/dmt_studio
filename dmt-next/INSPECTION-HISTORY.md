# 검사 이력·재입고 범위·Dummy·OT14 (v0.4.15)

## 작업자 검사 이력

공정 TXT 수집 중 대상 LOT의 **병합 전 원본**을 A PC에 보관합니다.
`모델_LOT_작업자_날짜 시각.txt`의 세 번째 항목이 작업자 코드입니다.
예: `MODEL_RXTEST-_admin_2026-11-18 132845.txt` → 작업자 `admin`,
검사 시각 `2026-11-18 13:28:45`. `..._192_010345.TXT`의 `192`도 작업자입니다.
구형 형식은 날짜를 알 수 없으므로 검사 일자를 추정하지 않고 수정 시각을 별도로 표시합니다.
파일명 LOT가 내용과 다르면 작업자 정보도 확인 불가로 표시합니다.

새 **작업자 검사 이력** 탭에서 LOT, StripID 또는 작업자로 검색합니다.
공정별로 작업자, 파일명 검사 시각, 원본 수정 시각, 불량 라인 수, 원본 경로를 표시합니다.
행을 선택하면 해당 Strip의 원본 헤더부터 EOS까지와 SHA256을 확인할 수 있습니다.
**선택 이력의 원본 TXT 저장**은 병합 결과가 아닌 전체 원본 파일을 바이트 그대로 저장합니다.
동일 원본 재수집은 중복 기록하지 않고 마지막 확인 시각만 갱신합니다.
파일 내용·수정 시각·경로 또는 공정이 달라지면 별도 이력으로 보관합니다.
따라서 과거 재작업 이력을 최종 집계 결과로 오해하면 안 됩니다.

이력은 `<A PC 앱 데이터>/inspection-history/history.sqlite`에 압축 원본과 함께 저장합니다.
일회성 파서 캐시와 구분하며, 30일 TXT 원본 정리 기능으로 삭제하지 않습니다.
서버와 B/C/D 클라이언트는 A PC의 공통 저장소를 사용합니다.
클라이언트는 관리자가 현재 허용한 원본 경로에 해당하는 이력만 조회·다운로드합니다.
업데이트 이후 실제 수집한 자료부터 쌓입니다. 과거 모든 LOT를 자동 재검색하지 않습니다.
검색은 최대 500건이며, 더 많으면 StripID·작업자·공정으로 범위를 좁힙니다.
이력이 없다는 사실만으로 미검사라고 판정하지 않습니다.

## 재입고 범위

IVS 분석/조회와 게더링 공통 설정에 같은 모델·LOT별 설정을 제공합니다.
**재입고일 이후만 수집**을 켜고 날짜를 지정한 뒤 **수집 범위 적용**을 누릅니다.
날짜는 A PC 현지 시각 00:00부터 포함합니다. 기존 최근 30일 TXT 제한도 유지됩니다.

- XML: 원본 수정 시각으로 먼저 필터한 뒤 파싱합니다.
- TXT: 파일명에 유효한 전체 검사 날짜·시각이 있으면 우선합니다.
  없으면 원본 수정 시각을 사용합니다. 파일 수정 시각만으로 내부 각 블록의 실제 검사 일자를 보장할 수는 없습니다.
- **기존 IVS XML 유지 · 결과 TXT만 재수집**: 같은 모델·LOT의 마지막 IVS JSON을 유지합니다.
  IVS 스캔 실행 시 NAS를 다시 읽지 않고 해당 기준 자료를 재사용합니다.
  기준 JSON이 없으면 먼저 기존 JSON을 열어야 합니다.
- 결과 TXT는 각 공정에서 다시 수집합니다. 범위 내 최신 Strip 결과를 사용하며
  예전 결과를 새 결과에 합치지 않습니다. 명시적인 EOS-only 블록도 최신 정상 검사 결과로 보존합니다.
- 수집 영수증에 범위를 기록합니다. 공정별 범위나 XML 기준이 맞지 않으면 성적서 생성을 막습니다.
  설정을 바꿨다고 기존 결과 파일 내용이 자동 변경되는 것은 아닙니다.

## 검사 블록 누락

수율 계산 결과의 **공정별 검사 이력 검증**에서 Strip별 IVS/VRS/FVI 상태를 확인합니다.
불량 0개 완료 블록과 결과 블록 자체가 없는 경우를 구분합니다.
검증된 모집단/IVS 기준 Strip에 세 공정 결과 블록이 전부 없으면 공식 성적서 저장을 차단합니다.
RPT에만 있는 Strip은 별도 표기하며, 그 사실만으로 집계 모집단이나 OT14 수량을 늘리지 않습니다.
한 공정 결과만 없는 경우도 표시하되, 모든 Strip이 세 공정을 모두 거친다고 가정하지 않습니다.

## Dummy 지정 코드

최신 XML의 Dummy 판정 `ivs_1`에서 아래 코드가 하나라도 나오면 그 코드로 전량 처리합니다.

`AI01 AI02 AU00 AU02 DR00 DR01 DR02 DR05 DR07 RT00 RT02 RT07 RT08 SM03`

BBT/OT14를 먼저 배정한 뒤 나머지 Unit에 지정 코드를 적용합니다.
**88 Unit / RPT 4좌표 / Dummy DR01 → OT14 4, DR01 84**입니다.
OT14는 기존 정책대로 수율 총 Unit과 불량 Unit에서 제외합니다.
Dummy 9999는 알람만 띄우며 `SM03_DUMMY9999` 전량 자동 변환을 하지 않습니다.
일반 Unit의 9999 허용 정책은 유지합니다. 예상 밖 복수 Dummy 코드가 발견되면
임의 선택하지 않고 경고 및 공식 저장 차단으로 처리합니다.
최신 XML 전량 코드와 SKI가 다르면 기존 좌표/수량 검증으로 확인해야 합니다.

## OT14 추출 예시와 CSV

현재 RPT 파서는 `[StripID]` 헤더가 있으면 그 Strip, 없으면 RPT 파일명을 사용합니다.
`X:숫자 Y:숫자 =` 패턴의 좌표를 읽어 Strip별 집합으로 중복 제거합니다.
**현재는 `=` 뒤 숫자나 원본 불량 코드로 필터하지 않습니다.** 이 기준은 이번 변경에서 유지했습니다.
RPT 폴더 바로 아래 `.rpt` 파일이 대상이며 하위 폴더를 재귀 검색하지 않습니다.

```text
[RXTEST-01]
X:001 Y:001 = 1 - SM03
X:001 Y:001 = 1 - DR01
[RXTEST-02]
X:002 Y:001 = 1 - OT14
```

본 계산 대상이 RXTEST-01뿐이면 OT14는 `(1,1)` **1개**입니다.
원본 두 줄이 있어도 한 번만 집계하고, 대상 밖 RXTEST-02는 추가하지 않습니다.
동일 좌표의 다른 공정 코드보다 BBT/OT14를 우선하며, SKI에 없더라도 해당 대상 Strip의 RPT 좌표는 보존합니다.

수율 계산 후 **OT14 좌표·RPT 원본 CSV**를 누릅니다. 한 CSV 안에 두 종류의 행이 있습니다.

- `OT14_COORDINATE`: Strip/X/Y별 유일 좌표, RPT 출현 수, 중복 행 수, 선택 범위, 최종 OT14 반영 여부, SKI 포함 여부.
- `RPT_RAW`: 원본 파일 경로, 행 번호, 원문, 원본 코드, 파싱 상태. 헤더와 파싱되지 않은 행도 포함합니다.

`final_ot14=0`, `duplicate_rows>0`, `UNPARSED_COORDINATE`, `NOT_ASSIGNED_CHECK`를 확인하면
대상 밖 좌표·중복 원문·파싱 누락 의심 행을 대조할 수 있습니다.
RPT 내용이나 파일 목록이 계산 후 바뀌면 CSV를 혼합 생성하지 않고 재계산을 요청합니다.
CSV는 Excel용 UTF-8 BOM이며 수식으로 실행될 수 있는 텍스트는 작은따옴표로 보호합니다.

## 繁體中文操作摘要

**作業員檢驗履歷**：輸入 LOT、StripID 或作業員，再選擇製程並搜尋。
點選資料列可檢查原始 Strip 區塊及 SHA256；按「儲存所選履歷的原始 TXT」可下載完整原檔。
新的完整日期檔名優先提供檢驗時間；舊格式僅有修改時間，不能將兩者混為一談。
履歷從更新後收集的資料開始累積，保存在 A 電腦，不會因 30 天 TXT 清理而刪除。

重新入庫時，請於 IVS 或 Gathering 共用設定選取日期並按「套用收集範圍」。
XML 依修改時間篩選；TXT 優先依檔名完整檢驗日期，無日期才依修改時間。
如僅重做結果檢驗，請勾選「保留原 IVS XML，僅重新收集結果 TXT」，再重新收集各製程 TXT。
不同範圍的資料不能直接混合產生正式報告。
零不良 EOS 完成區塊代表有檢驗紀錄；完全找不到區塊則須確認資料是否漏收。

Dummy 指定代碼會套用至扣除 BBT 後的其餘 Unit；88 Unit 扣除 4 個 BBT，DR01 為 84。
Dummy 9999 僅警示，不再自動改為 SM03 整片報廢。
良率計算後可匯出「OT14 座標與 RPT 原始資料 CSV」，比對唯一座標與每一行原始 RPT。
RPT 中同一 Strip 的相同座標只計一次；範圍外 Strip 不會自動加入良率母體。
