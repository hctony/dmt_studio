# IVS 대표 이미지·범위 조회·XML 읽기 개선 (0.4.6)

## 사용 방법

- IVS 전체 수집과 수율 집계는 모든 XML 불량 기록을 사용합니다. 이미지 목록에 표시하는 건수만 **코드별 기본 10세트**로 제한합니다. 1세트는 같은 검사 항목의 Sub2/Main/Sub1 조명 이미지(최대 3장)입니다.
- 화면의 전체 이미지 세트·경로별 후보 파일 수는 XML 항목을 기준으로 집계합니다. 실제 이미지 파일의 존재 여부는 선택·다운로드할 때 확인하며, 없는 파일을 실재하는 이미지 수로 확정하지 않습니다.
- **추가로 보기**에서 코드와 시작·끝 번호를 선택합니다. 번호는 해당 코드 전체 목록의 1 기준이며 끝 번호를 포함합니다. 예: 전체 100건이면 기본 1–10, 추가 11–30을 조회합니다. 기본 10건과 현재 선택 범위를 표시하며 한 번에 추가 범위 최대 200건입니다. 다음 범위를 선택하면 이전 추가 범위가 교체됩니다. A/D는 현재 표시 목록을 이동합니다.
- 다운로드 버튼에서도 코드와 범위를 선택합니다. 화면에 불러오지 않은 91–100번도 직접 받을 수 있습니다. 다운로드는 기본적으로 전체 범위가 표시되므로 필요한 구간을 지정하세요. 같은 경로를 가리키는 XML 중복 기록은 이미지 한 세트로 받습니다.
- 정렬 기준은 StripID, Unit, 면, 이미지 번호, 설비·Trial·폴더·XML 경로입니다. 새로운 데이터로 다시 수집하면 번호가 바뀔 수 있습니다.

## 처리 변경

기존 집계는 불량 기록마다 이미지 3장의 bmp/jpg/jpeg 존재 여부를 순서대로 확인해 원격 stat 요청을 3–9회씩 보냈습니다. 새 IVS 집계는 XML에 있는 이미지 주소만 기록하고, 실제 경로·확장자 확인과 이미지 바이트 읽기는 조회·다운로드 시점으로 옮겼습니다. 선택한 이미지 세트의 확장자는 폴더 목록 한 번으로 확인합니다.

XML 원문은 A PC의 `cache/nas-xml.sqlite`에 보관하며 B/C/D도 동일 캐시를 사용합니다. 매 스캔의 폴더 메타데이터를 새로 확인하고 NAS 호스트·포트·사용자·루트·파일 경로·수정 시각·크기가 같은 경우 재사용합니다. 폴더 목록 캐시는 연결별로만 유지하므로 새 스캔에서 새 파일을 다시 찾습니다. 갱신 중인 최근 5초 이내 파일, 크기/시간을 확인할 수 없는 파일, 읽는 동안 변경된 파일은 저장하지 않습니다. 내용이 8 MB를 넘는 XML은 원격에서 읽되 캐시에 저장하지 않습니다. 24시간이 지난 저장 내용은 다시 읽으며 캐시 DB 문제는 원격 읽기로 대체합니다. 크기·수정 시각 일치가 파일 내용의 동일성을 보증하는 것은 아닙니다.

IVS와 전체 XML Barcode 화면의 **XML 강제 다시 읽기 (캐시 무시)**로 원문을 다시 확인할 수 있습니다. 캐시에는 XML 원문이 있으므로 기존 원본처럼 A PC의 개인 데이터 폴더 안에서 관리하며 공개 저장소에 포함하지 않습니다.

256 KB 이상 XML은 한 연결에서 최대 4개 읽기 요청으로 미리 가져옵니다. 새로운 SSH 연결이나 작업 동시 처리 수를 늘리지 않습니다. [Paramiko SFTPFile.prefetch 문서](https://docs.paramiko.org/en/stable/api/sftp.html#paramiko.sftp_file.SFTPFile.prefetch)를 따릅니다. 취소 시 기존과 동일하게 해당 작업의 SSH 연결만 닫고 부분 집계를 수율로 전달하지 않습니다.

## 측정과 한계

스캔 결과 JSON의 `scan_metrics`에 총 시간, XML 원격 읽기 횟수·바이트·시간, XML 파싱 시간, 캐시 재사용 횟수, 폴더 조회·재사용 횟수, stat 요청 수를 저장합니다. IVS JSON 저장에도 이 값을 유지하며 화면 로그에 주요 횟수를 표시합니다. 기존 성능 측정 JSON은 PC 자원과 작업 전체 시간을 계속 기록합니다.

`python dmt-next/benchmark-ivs.py 결과파일.json`은 **실제 NAS에 접속하지 않는** 재현용 비교입니다. 동일 XML의 불량 160건에 요청당 2 ms 지연을 주며 BMP가 존재하는 경우와 이미지가 없는 경우를 비교합니다. 기존 이미지 확인은 각각 480회/1440회이고, 개선한 첫 XML 읽기는 stat 2회, 재조회는 1회입니다. 모든 경우 집계 결과가 같은지 확인합니다. 이 수치는 NAS 전체 처리 시간의 개선 배수를 뜻하지 않습니다. 실제 목록 조회·인증·전송·XML 크기·NAS 부하를 포함한 속도는 대만 A PC에서 같은 LOT의 첫 조회/재조회를 비교해야 합니다.

원문이 모든 세션에서 새로 생성되는 경우 캐시 이득은 작고, 이미 본 LOT·XML을 다시 조회할 때 이득이 큽니다. 최근 한 달 밖의 XML을 일괄 제외하지 않으므로 전체 LOT의 양품 Strip·분모가 누락되지 않습니다.

## 繁體中文

完整不良數量、比率及良率仍以所有 XML 記錄計算，影像列表每個代碼預設只顯示 10 組。1 組為同一檢查項目的最多 3 張光源影像。按「追加檢視」選擇代碼與起訖編號（從 1 開始，含結束編號），可檢視基本 10 組與目前所選範圍，每次最多追加 200 組。下載時也可指定尚未檢視的範圍。

影像數量以 XML 項目與候選路徑計數，實際檔案是否存在於檢視/下載時確認。未變更的 XML 可重用 A 電腦的快取；需要重新確認原文時勾選「強制重新讀取 XML」。結果 JSON 的 scan_metrics 記錄實際讀取與快取次數，請在 A 電腦以相同 LOT 比較首次與重複查詢。

OT14 改為包含檢查範圍內 Strip 的全部 RPT 座標，不因 SKI 缺少該座標而排除；相同座標只計一次，其他 Strip 的 RPT 不納入。
