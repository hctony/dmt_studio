# IVS 수집 중지·단일 불량률·클라이언트 종료 진단

IVS 스캔 옆 **중지** 버튼은 로컬과 원격 클라이언트에서 동일하게 작동한다. 요청한 작업의 SSH 연결만 닫아 대기 중인 SFTP 읽기를 해제하고, 정상적인 정리 절차를 거쳐 스레드를 끝낸다. 아직 NAS에 연결하는 단계라면 연결 제한 시간까지 기다릴 수 있다. Qt 스레드를 강제로 terminate하지 않는다. 중지된 부분 결과는 완료 JSON이나 수율 자동 입력으로 등록하지 않는다.

수집 완료 신호 뒤에도 네트워크 정리가 남아 있을 수 있으므로 실제 스레드 종료 전에는 다시 스캔할 수 없다. IVS·StripID·게더링 등 UI 작업은 별도 참조를 유지하여 종료 처리 중 작업 객체가 파괴되는 위험을 줄인다. 정상/오류/중지 결과와 연결 정리는 구분한다.

## 단일 불량률

- **불량 내 구성비:** 기존과 같이 해당 코드의 고유 불량 Unit / 전체 고유 불량 Unit × 100.
- **단일 불량률:** 해당 코드의 고유 불량 Unit / 전체 생산 Unit × 100.
- **전체 생산 Unit:** NAS에서 확인한 고유 Strip 수 × Strip당 Unit 수.

같은 Strip/Unit이 재검, 다른 조명, 앞뒷면에 중복 등장해도 코드별로 한 번만 센다. 한 Unit에 여러 코드가 있으면 각 코드에 포함되므로 단일 불량률을 합산하면 전체 불량률과 다를 수 있다. Dummy와 Rework 9998은 기존 Unit 불량 집계 규칙대로 제외한다. 최종 수율은 기존 BBT/SKI/X-out 등의 규칙을 추가로 적용하므로 IVS 원시 코드 비율과 판정 결과를 구분해야 한다.

Strip당 Unit 수는 모델별 저장값, 동일 모델 Gathering의 X×Y 또는 명시적인 NAS XML 행·열 메타데이터로 확인한다. 불량 좌표의 최댓값이나 불량 기록 개수로 전체 수량을 추정하지 않는다. 누락된 barcode, XML 파싱 오류, 모델 수량과 NAS 행·열의 불일치가 있으면 단일 불량률은 `—`로 표시한다. Unit 수를 수정하면 모델 설정에 저장하고 비율을 갱신한다.

IVS 수집은 불량이 없는 Strip의 barcode도 읽고, IVS XML에 식별자가 없으면 FC XML에서 확인한다. 여러 Trial/설비에 중복 등장한 Strip은 한 번만 센다. 특정 Trial을 선택했다면 분모도 해당 Trial 범위이며 화면에 **선택 Trial 전체 Unit**으로 표시한다. 이전 IVS JSON에는 전체 수량이 없을 수 있다. 같은 모델·LOT의 완료된 StripID 추출 결과가 있으면 그 목록을 사용할 수 있고, 없으면 재수집하거나 전체 StripID 데이터를 먼저 준비해야 한다.

전체 LOT 수집이 완료되면 검증된 전체 StripID 목록과 Unit 수를 수율 입력으로 자동 연결한다. 새 `dmt-studio-strip-population-v1` 목록을 사용한 수율 계산은 불량이 없는 Strip까지 분모에 포함한다. 집계 TXT에 없는 Strip에 대한 기존 검증 경고는 유지한다. IVS와 수율 Unit 수가 다르면 계산을 멈추고 모델 설정 및 Gathering X×Y를 확인하도록 안내한다. 기존 형식의 StripID JSON만 사용하는 계산은 기존 분모 처리 방식을 유지한다.

## 창이 닫히는 문제를 추적할 때

업데이트 후 재현되면 **B/C/D 클라이언트 PC와 A 서버 PC 양쪽에서 `진단 로그 내보내기`**를 눌러 JSON을 보관한다. 클라이언트 창이 닫혔다면 프로그램을 다시 열어 내보낸다. 로그는 업데이트·재실행 후에도 앱 데이터의 `diagnostics/`에 남는다.

기록 항목은 화면 프로세스 종료 사유(예: 메모리 부족, 충돌), 네이티브 종료 코드, 화면 닫기 요청, 앱 종료 요청, 분석 엔진 stderr/치명적 오류 스택, 마지막 작업·NAS 단계, 자원 샘플, 클라이언트 JS 오류 및 통신 중단 시각이다. 정상적인 탭 종료/절전/망 단절도 폴링 중단을 일으킬 수 있으므로 폴링 중단만으로 충돌이라고 단정하지 않는다.

로그에는 LOT·작업 경로가 포함될 수 있다. 접속 키·NAS 비밀번호는 로그 내보내기에서 제거하며 `.env`를 포함하지 않는다. 네이티브 crash dump는 PC에만 저장하고 자동 업로드하지 않는다. JSON 내보내기에는 dump 자체가 포함되지 않는다. 실제 현장 종료 원인은 이전 버전 로그만으로 확정할 수 없으며, 새 진단 로그를 분석해야 한다.

클라이언트에 전달하는 이미지 미리보기는 긴 변 1600px로 제한하고 큰 이미지에는 JPEG를 사용한다. 화면 로그는 최근 50000자만 전달한다. 백엔드의 원본 이미지와 전체 텍스트·기존 내보내기 데이터는 유지한다. 이 조치는 전송량과 화면 메모리 부담을 줄이지만 모든 종료 원인이 해결됐다는 뜻은 아니다.

## 동시 4개 시험

동시 처리 상한 1–4는 A 로컬 작업을 포함한다. CPU 8%, 메모리 32% 같은 낮은 수치는 시험 여유를 보여 주지만 NAS의 메타데이터 응답 지연과 완료/이미지 표시 순간의 메모리 피크를 대신하지 않는다. 2개와 4개를 실제 LOT로 끝까지 처리하여 시간·오류·메모리 피크를 비교한다. 측정 JSON의 작업별 `maxConcurrency`로 동시 실행 조건을 구분할 수 있다. 설정은 자동 변경하지 않는다.

## 繁體中文

IVS 掃描旁新增「停止」。僅關閉所要求工作的 SSH 連線，正常清理後結束，不會將部分結果帶入良率計算。連線建立中可能需要等候連線逾時。確認執行緒真正結束前不允許再次掃描。

新增「單項不良率」＝該代碼的唯一不良 Unit / 全部生產 Unit ×100。全部 Unit 由 NAS 唯一 Strip 數乘上每片 Unit 數取得，包含無不良的 Strip，並去除重測、照明及正反面的重複。原有不良組成比保留。分母不明、barcode/XML 遺漏或 NAS 行列與設定數量不符時顯示 `—`。完整 LOT 的已驗證清單會自動帶入良率計算，未出現在整合 TXT 的 Strip 仍保留檢查警告。

若用戶端視窗再次關閉，請在用戶端與 A 電腦兩側匯出診斷 JSON。紀錄包含畫面/分析程序結束原因、退出代碼、最後工作與資源資料。金鑰與 NAS 密碼會遮蔽，不包含 `.env`；原生 crash dump 僅保存在本機、不自動上傳。顯示預覽及日誌傳輸量已限制，原始資料與原有匯出保留。現場真正原因仍需依據新紀錄判定。
