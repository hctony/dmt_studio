# 0.4.9 성적서 검증·OT14 제외·미분류 코드 검토

0.4.11부터 9999는 생성 차단 예외입니다. 수량과 코드 그대로 집계·엑셀에 포함하며, 원본 조회와 선택적인 분류 기능은 유지합니다. UNKNOWN 및 불일치·수집·ITS 검증 조건은 유지합니다.

0.4.22부터 성적서 미리보기와 Excel에서 1111·170·OT06을 OT06으로 합산합니다. 원본 추적 화면에는 각 좌표의 원본 코드가 남습니다. OT14 좌표·RPT 원본 보기는 원격 클라이언트에서 바로 열 수 있고, 내 결과 다운로드의 CSV 바로 보기에서 저장한 CSV도 확인할 수 있습니다.

## 생성 조건

**성적서 엑셀 내보내기**를 누르면 하단 표의 **불일치만**과 동일한 기준을 검사합니다. 공정별 입력은 `합산 X-out(final_xout) != SKI(ski_xout_count)`, 기존 TXT 입력은 `xout_count != ski_xout_count`인 Strip이 한 개라도 있으면 생성하지 않습니다. 화면에서 전체/불일치만 중 무엇을 선택했는지와 무관하며 합계 행은 건수에 포함하지 않습니다.

UNKNOWN이 최종 배정 코드에 남으면 오류를 표시하고 생성하지 않습니다. 9999는 예외로 그대로 포함할 수 있습니다. 수집 미완료·ITS 검증 미완료·계산 후 원본 변경 차단은 유지합니다. 코드 분류로 좌표 차이를 숨기거나 원본 검증을 우회하지 않습니다.

## OT14 계산과 엑셀

OT14로 배정된 고유 `(StripID, X, Y)` 좌표를 총 Unit과 불량 Unit에서 각각 차감합니다. 원본 총 Unit 100개, 불량 10개 중 OT14 3개라면 총 Unit 97개, 불량 7개, 양품 90개이며 수율은 `90 / 97 × 100`입니다. 중복된 RPT/TXT 좌표는 중복 차감하지 않습니다. 선택된 Strip 범위를 넓히지 않으며 기존 RPT 적용 대상 결정 방식은 유지합니다.

RPT의 OT14뿐 아니라 공정 TXT에서 최종 OT14로 배정된 좌표도 제외합니다. OT14가 다른 공정 코드와 겹치면 기존의 좌표별 최종 배정 결과를 사용합니다. 원본 SKI·RPT·TXT 좌표와 하단 X-out 비교는 제외 전 데이터를 유지합니다. 모든 Unit이 OT14이면 총 Unit·불량 Unit은 0, 수율은 0으로 표시하며 0으로 나누지 않습니다.

성적서의 OT14 불량 열을 제거합니다. 별도 검증 영역에 다음 값을 기록합니다.

| 셀 | 내용 |
|---|---|
| H8 | OT14 제외 수량 |
| H9 | 제외 전 원본 총 Unit |
| H10 | 제외 전 원본 불량 Unit |
| H11 | 하단 표 불일치 Strip 수 (생성 시 0) |

G8:G11에는 설명이 표시됩니다. 기존 H6 불량 합계 검증은 OT14가 빠진 불량 열과 H3를 비교합니다. 코드 미리보기의 OT14는 검증용으로 남으며 불량률을 표시하지 않습니다.

## 미분류 코드 점검과 분류

1. 계산 시 UNKNOWN 오류를 확인한 뒤 **코드 미리보기**를 엽니다. 9999는 오류 없이 포함할 수 있으며 필요할 때 선택적으로 검토합니다.
2. 해당 코드와 좌표를 선택하고 TXT/RPT·SKI·XML 원문 및 계산 근거를 비교합니다. 원본 조회는 기존과 같이 A PC에서 수행합니다.
3. **분류 코드**(예: SM03, OT12)와 **분류 사유**를 입력합니다. 원본은 수정하지 않습니다.
4. **선택 좌표 분류**는 선택한 좌표에만 적용합니다. Ctrl/Shift로 여러 좌표를 선택할 수 있습니다. **현재 코드 전체 분류**는 현재 코드의 모든 페이지·Strip 좌표에 같은 코드를 적용하므로 확인창에서 수량을 검토합니다.
5. 남은 미분류 코드가 없고 불일치만 0개이며 기존 검증도 통과한 뒤 엑셀을 생성합니다. 분류 내역은 엑셀의 **분류 이력** 시트와 결과 JSON에 포함됩니다.

허용 대상은 최종 배정 코드가 정확히 9999·UNKNOWN인 좌표입니다. 기존 규칙으로 이미 `SM03_DUMMY9999`에 배정된 IVS Dummy 양폐는 기존 동작을 유지합니다. 원본에서 9999가 나왔더라도 최종 배정이 RPT의 OT14라면 OT14로 처리합니다.

분류 결과는 해당 PC/원격 세션의 `%APPDATA%/dmt-analysis-next/.../report-reviews`에 원본 이력·좌표·코드와 연결해 저장합니다. 동일한 입력으로 다시 계산하면 재사용하며, 입력 내용·좌표·원본 수정 시각 등이 바뀌면 새 계산에 이전 분류를 자동 적용하지 않습니다. **분류 초기화**로 해당 계산의 분류를 되돌릴 수 있습니다. 다른 클라이언트의 검토 결과를 자동 공유하지 않습니다. 사유·분류 코드·UTC 시각을 기록하며 임의의 정상 판정으로 좌표를 삭제하는 기능은 제공하지 않습니다.

## 繁體中文

產生成績書前，必須確認下方表格「僅不一致」為 0 筆，且最終分配代碼沒有 UNKNOWN。自 0.4.11 起，9999 例外允許直接納入統計及 Excel，仍可選擇檢查與分類。無論目前選擇全部或僅不一致，皆套用相同檢查；原有收集及 ITS 驗證亦保留。

OT14 依不重複的 StripID/X/Y 從總 Unit 及不良 Unit 各扣除，良品數不變。Excel 移除 OT14 不良欄，改於 H8 記錄 OT14 排除數量，H9/H10 為原始總 Unit/不良 Unit，H11 為不一致 Strip 數。原始座標與 SKI 比較不扣除 OT14，避免隱藏缺漏。

請於「代碼預覽」比較原始 TXT/RPT、SKI、XML，輸入分類代碼及必填原因，再使用「分類所選座標」或確認後「分類目前代碼全部座標」。支援 Ctrl/Shift 多選。原始資料不修改；分類結果與原始資料綁定，資料變更須重新檢查，可重設分類。Excel 另附分類歷程工作表。既有已分類為 SM03_DUMMY9999 的 Dummy 報廢規則保留。
