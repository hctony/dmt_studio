# LOT 기반 수율 자동 진행 설계

## 현재 코드에서 확인한 동작

- `core/utils.py:auto_find_bbt_skipdata_path`: `D:\KINSUS DATA\Backup` 바로 아래 각 폴더의 `*.rpt` 파일명에 LOT가 포함되면 첫 폴더 반환.
- `core/utils.py:auto_find_ski_file_path`: `D:\SkipData` 아래를 재귀 검색해 LOT가 파일명에 포함된 첫 `*.ski` 반환.
- `GatheringTab.on_lot_changed_smart`: 위 경로를 입력하고 Gathering/Yield QSettings에 저장. 검색 실패 시 기존 입력은 남음. Yield의 현재 화면 입력을 직접 갱신하는 동작은 없음.
- 수동 LOT 입력은 연결돼 있었으나 LOT 자동 입력 및 검색 선택은 `setText`만 호출해 `editingFinished`를 발생시키지 않았음. 이번 수정에서 이 두 경로를 연결.
- 기존 탐색에는 후보 순위, 최종 SKI 판별, 다중 후보 확인, LOT 경계 일치, 검색 루트 설정이 없음. 첫 파일을 최종 파일로 간주하면 안 됨.

## 권장 실행 흐름 (새 기능 설계이며 아직 실행기로 구현되지 않음)

IVS 화면의 **LOT 전체 분석 시작**으로 실행 컨텍스트를 고정한다.
모델/LOT, 적용 프로필, 입력 후보, 파일 수정 시각, 실행 ID를 보관한다.
스캔이 돌려준 실제 모델/LOT가 요청과 같은지 검사하며 실행 중 다른 화면 입력 변경은 이 컨텍스트에 섞지 않는다.

1. 사전 확인: NAS 및 공정 공유 경로 접근, 모델별 X/Y·Strip당 수량·X-out·제외 코드·공정 선택을 확인한다. X/Y는 총 수량만으로 유추하지 않는다. 필요한 값이 없으면 최초 1회 입력 후 모델 프로필에 보관한다.
2. 경로 탐색: 기존 기본 루트를 지원하면서 설정 가능한 루트 및 해당 모델의 이전 경로를 탐색 출발점으로 사용한다. 이전 경로를 현재 LOT의 정답으로 재사용하지 않는다. RPT/SKI 후보를 모두 수집하고 LOT 경계 및 가능한 파일 내부 식별자로 확인한다. 접근 불가와 검색 결과 없음을 구별한다. 다중 후보 또는 최신/최종 판단 근거가 부족하면 사용자에게 후보 선택을 요청한다. 검색은 작업 스레드에서 실행하고 진행 상태를 표시한다.
3. IVS: 기존 `IvsScanThread`를 실행하고 결과 JSON을 실행 폴더에 자동 저장한다. 불량 Unit 목록으로 전체 Strip 모집단을 추정하지 않는다. 필요 시 기존 StripID 추출 로직으로 모집단 JSON을 별도 확보한다.
4. Gathering: 기존 `GatheringWorker`를 VRS/FVI/IVS 선택에 따라 실행한다. 기존 중복 처리 및 재작업 날짜 선택을 재사용한다. 자동 결정 근거가 부족하면 `확인 대기`로 전환한다. `Gather_<공정>_<LOT>.txt`를 현재 실행 폴더에 저장한다.
5. Yield: 현재 실행에서 만든 TXT/IVS JSON/StripID JSON과 검증된 BBT·SKI, 고정한 모델 수량을 직접 연결해 `calculate_yield_summary_by_process`를 호출한다. 화면에 남은 다른 LOT 경로를 사용하지 않는다. 계산도 작업 스레드로 옮겨 UI 정지를 막는다.
6. 검증: 기존 `bbt_validation`, `ski_validation`, `ski_gather_xout_mismatch_rows`, `report_vs_ski_delta` 및 LOT/StripID/입력 누락 검사를 모아 결과 화면을 연다. 총 Unit·양품·불량·불량률, BBT/SKI 불일치, 제외 내역과 사용 파일을 표시한다. 사용자는 불일치 확인 및 최종 보고서 승인을 수행한다.

## 실행 상태 및 완료 조건

`사전 확인 → 경로 탐색 → IVS → Gathering → Yield → 검증 대기 → 승인 완료`

각 단계는 `실행 중 / 확인 대기 / 실패 / 취소 / 완료`를 별도로 기록한다.
스레드 종료나 파일 존재만으로 성공을 판정하지 않는다. 예외 또는 누락 공정이 있으면 최종 성공으로 표시하지 않는다.
이미지 미리보기 로딩은 IVS 분석 완료와 별개이므로 다음 단계 시작을 막지 않는다.
재실행은 새 실행 ID/폴더를 사용하며 기존 결과를 덮어쓰지 않는다.
동일 LOT 중복 실행을 막고, 실패 후에는 상위 입력이 동일한 단계까지만 재사용한다.
파일 변경 시 관련 캐시를 무효화한다.

기존 LOT 로그(`workflow_assistant.py`)는 관찰 기록/추천 도구다. 이를 실행기로 간주하지 않고,
새 상태 실행기가 단계 결과 및 자동 선택 근거를 이 로그에도 기록한다.

## 구현 순서 및 현장 검증

경로 후보 수집/검증 → 모델별 입력 프로필(X/Y 포함) → 단계 실행기/자동 저장 → 검증 화면 순서로 구현한다.
기존 버튼과 계산 함수를 재사용하되 파일 선택창에 의존하는 부분은 실행 컨텍스트 인자를 받도록 분리한다.
한국어·번체 안내를 제공한다.
대만 PC에서 최소 3개 LOT를 기존 수동 결과와 병행 비교하여 공정별 Strip 수·불량 수·최종 수율·BBT/SKI 차이가 일치하는지 확인한다.
다중 SKI, 재작업 날짜, 공정 누락, 접근 불가, 중복 Strip, 중도 취소 및 변경된 입력 재실행을 포함해 검증한다.
