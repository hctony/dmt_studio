# 기존 백엔드 유지 및 이관 현황

기존 `core/`, `workers/`, `ui/tabs/`가 기능의 기준이다. 전체 기능을 재작성하지 않고 기존 처리 함수를 Electron에서 호출하도록 연결한다. 현 시점 Electron이 원본 앱을 대체하지는 않는다.

## 확인한 저장·캐시 규칙

| 항목 | 기존 저장 위치/키 | 현재 조치 |
|---|---|---|
| 탭별 입력 | QSettings(DMT, DMT Analysis Studio) | 읽기 API 추가. 입력 UI 연결은 미완료 |
| 모델별 수율 | 작업 디렉터리의 yield_model_settings.json | 기존 파일 유지. 시제품 가져오기 사본은 아직 계산에 연결 안 됨 |
| 게더링 TXT 파싱 | 파일 경로·mtime·크기·LOT·파서 버전 | 원본 함수 재사용. 상주 프로세스에서 유지 |
| 게더링 파일 목록 | 기존 루트 디렉터리 mtime | 하위 파일 메타데이터까지 검사하도록 수정 |
| BBT 좌표·코드 | 기존 최댓값 mtime·파일 개수 | 모든 RPT의 이름·mtime_ns·크기 조합으로 수정 |
| SKI 좌표 | 파일 경로·mtime·크기 | 원본 함수 재사용 |
| LOT 자동 추론 | JSON 내용, 경로, TXT/SKI/PMK 앞부분 | 원본 함수 호출 API 추가 |
| 파일 선택 시작 경로 | 현재 입력 경로의 부모 | 누락된 Path/first_path_text import 수정 |

백엔드는 요청마다 종료하지 않는 JSON-lines 프로세스이며 앱 종료 시 종료된다. 현재 개발 실행에는 Python과 기존 dependencies가 필요하다. 배포용 백엔드 번들 및 Electron 설치 패키지는 아직 구성되지 않았다.

캐시 변경 확인에는 메타데이터 재조회 비용이 필요하다. 같은 파일 크기와 수정 시간을 인위적으로 유지한 내용 변경은 현재 방식으로 감지하지 못한다. 이 경우 캐시 비우기를 사용한다. 원본 모듈의 캐시 반환값을 수정하는 호출자의 영향과 장기 실행 메모리 증가는 추가 검토 대상이다.

## 화면별 아직 연결해야 하는 기능

- IVS: Trial 선택, 스캔 진행, 그룹 필터, JSON 입출력, 3광원 이미지·다운로드.
- StripID: Bundle 제한과 FC 조회, 결과 저장.
- 전체 XML: 스캔, 중복 위치, JSON 비교.
- 게더링: 공정 설정, 날짜 선택 대화상자, 중복 선택, 중지, 일괄 추출.
- Strip 검색: 기존 설비별 저장 경로와 검색 결과.
- 검사 통계: 날짜·설비 선택, 검사원 상세, 엑셀.
- 수율: 공정별 판정, 모델별 설정, 진단, Excel 템플릿 출력.
- Strip 진단: 누락·좌표·SKI 최종 검증과 검증 JSON.
- LM: 미리보기, BK 이동·PMK 재작성, 백업 결과.
- 테스트: 원본 테스트 실행·실패 재실행.

Qt worker에는 결과 Signal과 사용자 응답을 기다리는 동작이 있으므로 단순 함수 호출로 대체하지 않는다. 작업 상태 및 응답 프로토콜을 연결해야 한다.

## 검증

`python -m unittest discover -s dmt-next -p test_legacy_bridge.py`

네 가지 회귀 테스트: 하위 TXT 추가, 오래된 RPT 변경, 경로 선택 helper, 여러 요청 동안 SKI 캐시 유지 및 비우기. 현장 NAS 연결과 실제 데이터 결과 일치 검증은 아직 수행하지 않았다.
